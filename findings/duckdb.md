# DuckDB through SQLFrame (`spark_connect.ipynb`, `ENDPOINT = "duckdb"`)

Not Spark and not Spark Connect: [SQLFrame](https://github.com/eakmanrq/sqlframe) 4.4.0 gives a PySpark `SparkSession` that runs in-process on DuckDB 1.5.5, turning DataFrame code into SQL and translating Spark SQL with sqlglot. Tables are Iceberg in the same OneLake catalog as Sail, through DuckDB's iceberg extension, attached as in [djouallah/iceberg-probe-native](https://github.com/djouallah/iceberg-probe-native) (`STAGE_CREATE_TABLES false`, `SKIP_CREATE_TABLE_METADATA_UPDATES true`, `ACCESS_DELEGATION_MODE 'none'`, an `access_token` storage secret).

**24 PASS, 16 FAIL, 1 WRONG of 41** (run of 2026-10-01, per check: [`local/duckdb.csv`](local/duckdb.csv)).

- **DataFrame API and Spark SQL queries:** everything passes (`createDataFrame`, joins, `pivot`, windows, CTEs, `GROUPING SETS`, `toPandas`, ...).
- **`spark.sql()` only runs queries, by design** (`sqlframe/base/session.py`, `sql()`): it accepts a SELECT, or a CREATE / INSERT whose body is a SELECT (CTAS, `INSERT ... SELECT`), and raises `ValueError("Unknown expression type provided in the SQL...")` for everything else. The maintainer confirmed it in [sqlframe#475](https://github.com/eakmanrq/sqlframe/issues/475) (2025-08-24, still open): "assumes what is passed into SQLFrame session `sql` method is a SELECT expression ... doesn't currently support DDL/DML statements". DML exists only through SQLFrame's own `Table` class (`session.table(...).update/delete`), not PySpark API. So `USE SCHEMA`, `SHOW NAMESPACES`, `DESCRIBE TABLE`, `DROP TABLE`, `UPDATE`, `DELETE` and `MERGE` can't run. `CREATE SCHEMA` and `CREATE TABLE ... PARTITIONED BY` (a CREATE with no SELECT body) crash on `'NoneType' object has no attribute 'copy'`, `INSERT INTO ... VALUES` on `'Values' object has no attribute 'ctes'`. The same statements fail the same way on a plain in-memory DuckDB, so it's SQLFrame, not OneLake.
- **`saveAsTable(mode="append")` never creates the table** (`sqlframe/base/readerwriter.py`, `saveAsTable`): append just calls `insertInto`, a plain INSERT, where Spark creates a missing table. `saveAsTable(name, format=...)` raises `NotImplementedError`. `writeTo().append()` isn't implemented. With no schema and no table, `catalog.currentDatabase` and `INSERT OVERWRITE` fail too.
- **UDFs:** no `F.udf` and no `F.pandas_udf` ("Not currently", [sqlframe#24](https://github.com/eakmanrq/sqlframe/issues/24), 2024). `spark.udf.register` + SQL works.
- **WRONG `date functions`:** `date_add(to_date(...), 30)` returns a timestamp, not a date.
- **No `spark.conf`:** the session has no `conf`, so the Connect cell sets DuckDB's `TimeZone` directly.
- DuckDB itself writes Iceberg on OneLake fine (CREATE TABLE, INSERT, UPDATE, DELETE, MERGE, DROP all work in plain DuckDB SQL); the gaps above are SQLFrame's Spark layer.
